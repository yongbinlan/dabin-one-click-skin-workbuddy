WorkBuddy 换肤启动器 —— 使用说明
========================================

【日常：只有一件事】
  双击桌面「WorkBuddy」图标（开始菜单、任务栏的也一样）。
  皮肤会自动带上，没有别的步骤。

  这三个入口都已指向本目录的 workbuddy-skin-launcher.vbs：
  它先启动 WorkBuddy，再自动注入「夜街」皮肤 + 你选的壁纸，
  约 2 秒完成、无窗口、不抢焦点、不留常驻进程。


【换壁纸 —— 三种方式，都很快】

  ◆ 方式一：双击 壁纸选择器.lnk     ★ 推荐，所见即所得
      双击后会弹出一个小窗口：壁纸缩略图成排，点一张就换一张；
      「淡 / 中 / 浓」三个按钮调壁纸透出多少；
      底部还有「选一张图…」「刷新」「打开壁纸库」「关闭」。
      换完不用重启 WorkBuddy，界面当场就变。

      · 想用自己图库里的图（最常用）：
          点「选一张图…」→ 在弹出的窗口里**直接点中一张图** → 确定。
          只拿这一张，跟别的图没有任何关系。
          （也可以改选一个**文件夹**：界面会把里面的图列出来供你挑，
            再点哪张换哪张。想先翻着比较时用这个。）
          点中的那张会自动收进壁纸库一份，以后重启也还在。

      · ★ 「列出来」和「加进来」是两回事，别搞混：
          「列出来」= 只是预览。这时候一张都没换、也一张都没进壁纸库，
                     界面上会有金字提示写明这一点。
          「点一张」= 只把这一张复制进壁纸库，其他图原封不动。
          你原来的图库（D:\我的图片）里有多少张，就还是多少张，
          界面上不会、也不需要把它们都收进来。

      · ★ 壁纸库是越攒越多的：每收一张，库里就多一张，
          库里原来那些**一张都不动**（不移动、也不删除）。
          想留着好几张轮换，正常收图就行，不需要额外加什么参数。

      · 点完之后，界面最下面那行会把账算给你看，例如：
          「只收进了这 1 张：xxx.jpg　壁纸库现有 3 张（旧的一张都没动）；
            D:\我的图片 里的 47 张原图也没有被移动、也没有被删除。」
          心里没底时，看这一行就够了。

      · 在文件夹视图里点完一张后，界面会留在原来的目录里（不跳走），
        只有那一张会多出标记（直接选中的那张图则会回到壁纸库视图）：
            「已在壁纸库」（绿字）        = 库里已经有这张了
            「已收进库 · 正在使用」（金字）= 就是刚收进来、现在正用的这张
          其余图照旧显示 —— 一眼就能确认没丢东西。
          想看壁纸库本身，点状态行右边的「返回壁纸库」。

      · 或者把图片从「资源管理器」直接拖进这个窗口，效果完全一样。

      · 缩略图上写「无缩略图」不代表不能用 —— 系统自带的预览控件解不了
        webp / avif 这两种格式，但换上去完全正常，点它就行。

      · ⚠️ 注意：「打开壁纸库」只是打开壁纸库那个文件夹，
        不会自动换壁纸。要加图请用上面两种方式（选一张图 / 拖进去），
        或者把图拷进壁纸库之后再点「刷新」。

  ◆ 方式二：双击 换壁纸.cmd
      双击打开一个黑窗口 → 列出壁纸库里所有图 → 输入编号回车，就换好了。
      想加入新图：把图片文件**直接拖到 换壁纸.cmd 的图标上**，
      它会自动收进壁纸库并立刻换上。

  ◆ 命令行（要一次做多件事时用）
      node tools\set-wallpaper.mjs           列出壁纸库 + 当前状态
      node tools\set-wallpaper.mjs use 2     按编号换

      收图（库里已有的图一张都不动，就往库里多添这一张）：
      node tools\set-wallpaper.mjs add "<图片路径>"

      清库（可选，平时用不到）：把库里除当前壁纸之外的图移到归档目录
      （是移到归档、不是删除，想找回随时能拷回来）：
      node tools\set-wallpaper.mjs prune

  不管用哪种方式，以后重启 WorkBuddy 都会自动用你选的这张。


【调壁纸透出多少】—— 三个档

  ◆ 双击 调强度.cmd，按 1/2/3 选：
       1 = 淡    壁纸最明显，氛围最好
       2 = 中    默认，平衡（推荐日常用）
       3 = 浓    文字最清楚，看代码时用
     （壁纸选择器.hta 里也有这三个按钮，等效）

  ◆ 或命令行：
       node tools\set-wallpaper.mjs intensity 淡
       node tools\set-wallpaper.mjs intensity 中
       node tools\set-wallpaper.mjs intensity 浓

  换壁纸的时候也可以顺便定档：
       node tools\set-wallpaper.mjs use 2 浓

  带图的界面实拍（视觉验收留证）：
       docs\picker.png         壁纸库视图
       docs\picker-browse.png  选了文件夹之后的视图

  说明：不管哪个档，代码块和 diff 都保持高不透明，
        不会为了好看牺牲可读性。


【关掉皮肤】
      node tools\set-wallpaper.mjs none

  立刻恢复成 WorkBuddy 原生界面，且下次启动不会自己装回来。
  想恢复：双击 调强度.cmd 选一档，或跑 node tools\set-wallpaper.mjs use 1


【手动操作】双击本目录下的文件
  注意：.cmd 和 .hta 都得**双击**才会运行；单击只是选中，
        右边出现预览窗格 —— 这也是「点了怎么没反应」最常见的原因。

  壁纸选择器.lnk
      ★ 双击这个：带项目图标的入口，打开的就是下面这个图形界面。

  壁纸选择器.hta
     程序本体（上面的 .lnk 指向它）。文件图标由 Windows 的扩展名关联决定，
     跟文件里写什么无关，所以它显示的是系统默认的 HTA 图标 —— 这是正常的，
     不是没装好。
     图形界面：点缩略图换壁纸、点按钮调档位、
     点「选一张图…」直接挑一张换上（也可以选文件夹进去挑）；
     也可以把图直接拖进窗口。详见上面。

  换壁纸.cmd
     列出壁纸库，输入编号即换。
     把图片拖到它图标上 = 收进壁纸库并立刻启用。

  调强度.cmd
     按 1/2/3 选「淡 / 中 / 浓」，调壁纸透出多少。

  注入皮肤.cmd
     立即给"当前正在运行的" WorkBuddy 换肤。
     什么时候用：皮肤突然没了，或想手动补一次。

  还原原生.cmd
     移除皮肤和壁纸，回到 WorkBuddy 原生界面。
     只移除注入的样式，不碰任何应用文件，可随时再注入回来。
     什么时候用：想对比，或皮肤出问题时先还原再排查。

  查看状态.cmd
     只读：显示皮肤是否生效 + 最近 20 行日志。
     什么时候用：排查问题的第一步。


【换颜色】
  1. 打开 themes\night-street\assets\legacy-skin-workbuddy.css
  2. 改开头这四个颜色：
       --heige-accent      强调色
       --heige-secondary   次要色
       --heige-surface     底色
       --heige-text        正文色
  3. 命令行运行：
       node tools\build-theme.mjs
     它会重新生成 workbuddy.css，并自报「规则块 / 令牌 / 残留」三项
  4. 重新打包（见 README.md 的「主题工程」一节）
  5. 双击 注入皮肤.cmd 看效果

  当前「夜街」配色：
       --heige-accent      #e0b45c   暖金
       --heige-secondary   #6b8fa8   雾蓝
       --heige-surface     #12141d   深墨
       --heige-text        #f1e9dc   米白


【出问题时】
  1. 先双击 查看状态.cmd
  2. 再跑   node tools\verify-launcher.mjs     （回归自检，约 2 秒）
  3. 壁纸"看不见"时，跑这个看是谁挡着：
       node tools\diag-occluders.mjs
     它会列出所有面积大又不透明的容器，按面积倒序。
  4. 日志在 logs\launcher.log

  双击了没反应 / 窗口一闪就没？
     · 先确认是**双击**，不是单击。
     · 若是 .cmd 一闪而过：说明有出口漏了 pause。把 换壁纸.cmd 里
       所有分支都汇到 :DONE 再统一 pause（已经这么改了，别再改回去）。
     · 若是 壁纸选择器.hta：屏幕上可能已经开了一个窗口，但在别的程序后面。
       在任务栏找「WorkBuddy Wallpaper Picker」。

  在壁纸选择器里选了图，界面却没变化？
     · 「打开壁纸库」只是打开壁纸库那个文件夹，它不会换壁纸。
       要换图请点「选一张图…」，或把图片直接拖进窗口。
     · 点了「选一张图…」没弹出选择框？
       到这个目录手动把图拷进来，再点「刷新」也一样：
         <工程目录>\wallpapers
     · 界面最下面那行状态会写明每一步的结果（成功，或失败的原因）。
       先看那一行，就知道卡在哪一步了。
     · 反复选同一张图不会把壁纸库塞满 —— 会自动复用已有的那一份。

  在壁纸选择器里列出来一堆图，点了一张之后界面就只剩一张？我的图呢？
     · 一张都没丢，也一张都没删。这里有个特别容易看混的地方：
       选了文件夹之后，界面列的是**那个文件夹里的图**（只是预览），
       并不是壁纸库本身 —— 想看壁纸库，点状态行右边的「返回壁纸库」。
     · 点一张图只做两件事：
         ① 把这一张**复制**一份进壁纸库（原文件不动、不改名）
         ② 立刻换上它
       壁纸库里原来那些图**一张都不动**：不移动、也不删除，库里只是多一张。
       你原来的图库（比如 D:\我的图片）里有多少张，还是多少张。
     · 万一真想清空壁纸库、只留当前这张（平时用不到）：
       node tools\set-wallpaper.mjs prune
       它会把库里其他图**移到归档目录**（是"移"不是"删"）：
         <工程目录>\wallpapers-archive
     · 界面里列出的几十张图**只是预览**，不等于已经加进来。
       真正进了壁纸库的，卡片下面才会有标记：
         绿字「已在壁纸库」        = 库里已经有这张了
         金字「已收进库 · 正在使用」= 就是刚收进来、现在正用的这张
       一张标记都没有，就说明一张都还没进库。
     · 为什么要"复制一份"而不是直接引用原图：
       只记外部路径的话，原图一被移动、改名或删除，壁纸就失效了。
       所以用哪张就复制哪张进来，保证以后重启还在、也保证原图随便你整理。
     · 界面最下面那行每次都会把账目写清楚：
       收的是哪张 / 旧图去哪了 / 原来那个目录几张未动。
       觉得不对劲时，先看这一行。

  .cmd 双击后满屏乱码 / 或弹出一串"不是内部或外部命令"？
     两种情况，都靠同一个脚本修：
       · 满屏乱码   = 编码被写成了 UTF-8（正确应为 GBK 无 BOM）
       · 报"不是内部或外部命令"、还把你写的注释当命令跑
                    = 行尾被写成了裸 LF（正确应为 CRLF）
     修复方式（用 PowerShell 跑，不要在 bash / cmd 里跑）：
       & "<工程目录>\tools\_fix-cmd.ps1"
     它会把 launcher\*.cmd 一次性规范成 GBK + CRLF，幂等，可以反复跑。
     然后看 logs\fix-cmd.log 确认结果（正常应看到 verdict=OK、lf_after=0）。
     注意：这个脚本必须保持纯 ASCII，加中文注释会让它自己坏掉。

  用记事本打开 壁纸选择器.hta，看到一堆 \uXXXX 而不是中文？
     这是正常的，别去"修"它。这个界面跑在系统的 IE 内核上，而它对文件
     编码的猜测很不确定，猜错就是满屏乱码、且极难排查。所以生成器把
     所有中文都转成 \uXXXX 转义，产出的 .hta 是**纯 ASCII** ——
     这样无论按哪种编码解析，结果都一致。
     要改界面请改 tools\picker.template.hta（那里是正常中文），
     然后重新生成：
       node tools\build-wallpaper-picker.mjs
     生成器会自己做语法校验（真的把代码交给解析器解析）、ES5 合规检查、
     以及「脚本里引用的 WIN.xxx 常量是否真的定义了」这类一致性检查。
     想连界面自检一起跑（会短暂拉起一次不可见的界面）：
       node tools\build-wallpaper-picker.mjs --selftest

  放心：皮肤层的任何故障，最坏结果只是「没皮肤」，
  绝不会让 WorkBuddy 打不开 —— 因为「启动应用」由 .vbs 负责，
  不依赖 node，也不依赖注入脚本。


【想换新皮肤？】
  目前本机只有「夜街」这一套皮肤（实测确认：本机 4 份皮肤 CSS
  的配色完全相同，是同一套的不同副本）。
  但「壁纸」是可以随便换的（见上面），而且换起来比换皮肤方便得多。
  要做多皮肤切换，得先有第二套皮肤素材 ——
  可走 CodeDrobe 的「参考图 → 主题」流程生成，
  参考 README.md，或直接问 AI 助手。


【目录速查】
  壁纸选择器.lnk              ★ 双击：图形界面换壁纸 + 调档位（带项目图标）
  壁纸选择器.hta              程序本体；上面的 .lnk 指向它
  换壁纸.cmd                  ★ 双击换壁纸 / 拖图进来加图
  调强度.cmd                  ★ 双击选「淡 / 中 / 浓」
  tools\set-wallpaper.mjs     上面三者背后的命令（要批量/脚本化时用）
  tools\picker.template.hta   壁纸选择器的模板（要改界面改这里，是正常中文）
  tools\build-wallpaper-picker.mjs
                              模板 → 纯 ASCII 的 .hta，含四道构建期校验
  tools\launcher.mjs          等 CDP → 注入主题 → 注入皮肤层 → 自检
  tools\verify-launcher.mjs   回归自检（12 项断言，约 2 秒）
  tools\diag-occluders.mjs    遮挡诊断：谁把壁纸挡住了
  tools\cdp-probe.mjs         只读诊断：CDP + 四层令牌实测值
  tools\shot.mjs              给当前界面截图（WorkBuddy 渲染层）
  tools\_shot-picker.mjs      给壁纸选择器界面截图（视觉验证用）
                              加 browse 参数可截「选了文件夹」之后那个视图
  tools\_shot-screen.ps1      上面那个的截屏实现（必须纯 ASCII）
  tools\_orphans.mjs          清掉挂着的界面进程（清理用）
  tools\build-theme.mjs       配色 → 主题 CSS 生成器
  tools\_fix-cmd.ps1          .cmd 规范成 GBK + CRLF（加/改 cmd 后跑它）
  wallpapers\                 壁纸库 + current.json（当前选择）
  ..\wallpapers-archive\      清理壁纸库时的归档目录（是移不是删）
  docs\picker.png             壁纸选择器实拍（视觉验收留证）
  docs\picker-browse.png      同上，选了文件夹之后的视图
  logs\launcher.log           运行日志
  ..\backup\                  原始快捷方式备份（可回滚）
